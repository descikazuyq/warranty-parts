# 本地保修资格与备件承诺

本机程序调用的 Go 包：登记产品保修信息、备件库存与保修请求，按调用方给定的
当前时刻判断保修资格，并对备件进行承诺预留、分批使用与取消。全部状态保存在
进程内，使用一把互斥锁保证并发安全；`Ready()` 基线行为保持不变。

## 使用

```bash
go test ./...
```

## 典型流程

```go
s := warranty.NewStore()

// 1. 登记：产品（购买时刻、保修天数、除外故障代码）、备件（初始库存）、请求。
_ = s.RegisterProduct("P1", purchaseTime, 365, []string{"BROKEN_SEAL"})
_ = s.RegisterPart("PART-A", 100)
_ = s.SubmitRequest("REQ-1", "P1", "NOISE")

// 2. 按当次时刻预留承诺：每次预留都重新判断资格；到期时刻必须晚于当前时刻。
c, err := s.Reserve("COMMIT-1", "REQ-1", "PART-A", 10, expiry, now)

// 3. 分批使用：每次带全局唯一使用编号，扣减承诺未用数量与实物库存。
u, err := s.Use("USE-1", "COMMIT-1", 4, now)

// 4. 取消：只释放未用数量；到期自动失效并释放余量，无需另做清理。
c, err = s.Cancel("COMMIT-1", now)

// 5. 查询：按请求看资格依据/拒绝原因/关联承诺；按备件看实物剩余/占用/可承诺/明细。
rv, _ := s.RequestView("REQ-1", now)
ps, _ := s.PartStatus("PART-A", now)

// 6. 预留处理历史：按请求看每次预留提交当时的结果与依据，不需要当前时刻。
hist, _ := s.ReservationHistory("REQ-1")
for _, e := range hist {
    // e.Seq 严格递增；e.Outcome 是成功或具体错误类别；
    // e.Eligibility / e.Stock 是提交当时的资格依据与处理前库存快照。
    _ = e
}
```

## 规则要点

- 产品、备件、请求编号重复登记一律报错（`ErrDuplicateID`）且保留原记录。
- 购买时刻不得晚于当前时刻；保修天数为正整数；保修期自购买时刻起按每天
  二十四小时计算，自保修截止时刻起算过保；命中除外代码必须拒绝；过保与除外
  同时成立时拒绝原因会列出两项。
- 可承诺数量 = 剩余实物库存 − 所有有效承诺的未用数量；库存不足、未知请求或
  备件、不合格请求都不占用数量。
- 预留与使用均支持幂等重试：同编号同内容返回首次结果，换内容报
  `ErrConflict`；成功的使用在承诺取消或到期后重试仍返回原结果。
- 使用数量超过承诺未用数量时整次失败；已全部使用的承诺不再接受新使用。
- 并发预留同一备件时，有效承诺未用总量不会超过剩余实物库存。

## 预留处理历史

- 对已登记请求，每次**首次预留成功**及**每次失败提交**都留下一条记录；
  记录含本次提交的承诺编号、备件编号、数量、到期时刻、调用方给定的当前时刻，
  以及成功或具体错误类别（`succeeded`/`invalid_param`/`conflict`/`not_found`/
  `ineligible`/`insufficient_stock`）。序号在请求内严格递增，按实际处理次序
  排列，提交时刻相同或前后颠倒都不改变次序。
- 成功、不合格、库存不足的记录还保存当次的购买时刻、保修天数、保修截止时刻、
  是否命中除外代码、全部拒绝原因（过保与除外同时成立时两项都保留），以及
  **本次提交处理前**的实物剩余、有效占用和可承诺数量。缺少产品或备件、参数
  无效、编号冲突的记录依据明确为空，不用合格或零库存代替缺失。
- 同编号同内容的成功重试不追加历史、不重复占用；同编号改内容报 `ErrConflict`，
  失败记录挂在本次提交指定的已知请求下（即使编号原属另一请求）。失败提交不
  占用承诺编号，条件满足后可用同编号重新提交；早先失败记录不被后来成功覆盖。
- 未知请求的提交仍按原约定报错，不创建请求或历史；关联产品尚未登记的已知
  请求也能查到它的失败历史。承诺随后被使用、取消或到期，历史中的依据与数量
  不随之改变。
- `ReservationHistory(requestID)` 不需要当前时刻：空编号返回 `ErrInvalidParam`，
  未知请求返回 `ErrNotFound`，已知请求无记录返回空列表。返回的列表及拒绝原因
  均为快照副本，调用方修改不影响保存的历史、后续查询或原有业务记录。历史只
  保存在当前仓库实例中，不影响资格查询、预留、使用、取消和库存查询的既有约定。
